# تشغيل Tijvorya 2.1 — Merchant Website Builder

## الجديد في 2.1
عند دخول تاجر جديد أو تاجر لم يكمل إعداد موقعه، يتم تحويله إلى معالج إعداد احترافي يجمع بيانات النشاط ثم يبني له تلقائيًا موقع متجر متجاوب من ثلاث صفحات:

1. **الرئيسية** — الغلاف والهوية، المنتجات المميزة، الأقسام، الريلز، معلومات الثقة وقصة مختصرة.
2. **المنتجات** — كتالوج كامل مع البحث، الفلترة حسب القسم والترتيب.
3. **عن المتجر** — قصة النشاط، العنوان، ساعات العمل، مناطق التوصيل، سياسة الاستبدال ووسائل التواصل.

يمكن للتاجر الرجوع لاحقًا إلى **موقع المتجر / Website builder** من لوحة التحكم لتعديل بياناته، كما تبقى إعدادات المتجر والثيم متاحة في قسم **إعدادات المتجر**.

## المتطلبات
- Node.js 20.9 أو أحدث
- npm
- مشروع Supabase
- حساب Cloudinary للوسائط
- مفتاح OpenAI اختياري للميزات الذكية الحية

## التشغيل المحلي

```bash
copy .env.example .env.local
npm ci
npm run dev
```

افتح `http://localhost:3000/ar`.

## قاعدة البيانات

### مشروع جديد
نفّذ الملف كاملًا:

```text
supabase/schema.sql
```

### مشروع Tijvorya 2.0 قائم
نفّذ مرة واحدة من Supabase SQL Editor:

```text
supabase/migrations/20260814_v2_1_merchant_websites.sql
```

هذه الترقية تضيف بيانات موقع التاجر إلى جدول `stores`. المتاجر القديمة ستظهر لها شاشة الإعداد عند أول دخول للتاجر حتى تُستكمل البيانات المطلوبة.

## التحقق قبل النشر

```bash
npm run typecheck
npm run lint
npm run build
```

أو:

```bash
npm run verify
```

## روابط مهمة
- إعداد موقع التاجر: `/ar/merchant/onboarding`
- إعدادات المتجر: `/ar/merchant/store`
- الموقع العام: `/ar/store/{slug}`
- المنتجات: `/ar/store/{slug}/products`
- عن المتجر: `/ar/store/{slug}/about`

## النشر
- اضبط متغيرات `.env.example` في منصة الاستضافة.
- اجعل `NEXT_PUBLIC_DEMO_MODE=false` في الإنتاج.
- نفّذ ترقية قاعدة البيانات قبل نشر نسخة 2.1.
- لا تعرض مفاتيح الخادم الحساسة في المتصفح.
- استخدم HTTPS ونطاقًا رسميًا.
